# 改版纪律

1. **只改部署源**：一切改动先落在 VM ~/workspace/butler-build/AliceButler/ 的源文件，禁止直接改 PC 上的运行副本；PC 副本与源不一致时以源为准重新部署。
2. **只走部署脚本**：桌宠与 runner/watchdog 的上线只走 ~/workspace/tools/deploy-pet.sh（runner 换版另需重启 AliceButler 任务并验心跳）。部署完成的判据是脚本的 probe 通过＋对应冒烟项全绿，不是「脚本没报错」。
3. **投递必回读**：往 jobs/ 投任何任务、往 outbox 投任何回复，写后回读校验；完成以 done 回执/seen 搬运为准（acltest 教训）。
4. **原子投递**：四条文件通道一律临时名＋rename，见 PROTOCOL.md。
5. **配置与代码的边界**：轮询间隔、看护阈值、缓存与条数上限、动作权重表进 butler-config.json（改配置也要走部署并留记录）；物理手感常数（弹簧/重力/恢复/摩擦）与协议常量留在代码命名常量里，不进可写配置；ACL、锁路径、计划任务名永不进配置。
6. **新动作入池流程**：片段先过量化管线入 assets，再在片段描述表登记 name/fps/mode/时长，权重改配置不改代码；接线改动单独一步部署验证。
7. **动哪块验哪块**：改播放引擎验帧推进与内存；改状态机验拖拽/下落/睡眠/唤醒全路径；改桥验聊天全环（真发一条走通）；改 runner 验投递/停止不复活/崩溃重启三件套。
8. **回滚优先**：部署保留 AlicePetNew.prev.exe；行为修复尽量留旧路径开关；出问题先回滚再分析，不在生产副本上热修。
9. **记录**：每次部署与架构变更记入当日日志（~/memory/YYYY-MM-DD.md）；阈值类变更同步改 butler-config.json 与 ARCHITECTURE.md 的阈值表。
