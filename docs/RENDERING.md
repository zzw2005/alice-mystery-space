# 第七批渲染实测

基线 `e04d085`。Electron 45.3.3，Linux Xorg dummy 输出，X11，标称 60 Hz（主输出 60.01 Hz），Noto CJK 字体。使用独立桌宠根目录与 Electron 用户目录。13 段 WebM 的 SHA-256 逐一与基线核对。Windows 真实显示器与桌面合成器的结果待真机审核。

## DPI、跨屏与可读性

每档启动一个独立 Electron 实例，`--force-device-scale-factor` 分别设为 1.0、1.5、2.0。每次记录 Electron 的 DIP bounds、页面的 CSS viewport 和 X11 实测像素尺寸。单屏起步，接通第二输出，用 XTest 鼠标按下角色、越过屏界、在第二屏松手并等角色落定。保存副屏位置后关闭该输出，确认回主屏，再把主屏从 1364×1024 改为 1024×768。每个用例包含三次本体和三次透明位置的原生光标采样，通过主进程的鼠标穿透状态判断命中。

## 透明边缘与交叉淡化

在 1.0 档通过真实 Chromium CSS 视频合成截图。两路均 seek 到 1.020 s 后停住，切换样本取 `idle → wave` 的 50%/50% 槽位。按生产 DOM 的隔离和堆叠规则，把纯色背景放在角色隔离层外面，覆盖浅 `#f0f0f0`、中 `#808080`、深 `#202020`；透明截图用于计算参考。每种模式 3 张稳态背景、3 张中点背景，加中点与两张单轨的透明输入。评估范围是 Chromium 合成；系统桌面合成由 Windows 真机补验。

- 轮廓定义为透明截图 alpha ≥ 128。光晕宽度是在轮廓外、任一 RGB 通道相对纯背景变化 ≥ 3 的像素，到最近轮廓像素的欧氏距离。
- 边缘像素取 alpha 16–239，共 862 个。参考 RGB 为从透明截图按直通 alpha 在纯背景上合成的值，另计算 sRGB → D65 Lab 的 ΔE76。中点参考为两路预乘像素的等权平均，比较两路输入 alpha 均 ≥ 250 的 21,800 像素。

## 帧同步

仓库的 13 段视频均为 24 fps。30 fps 试验把同一 idle 流复制到临时应用目录，用 FFmpeg `-itsscale 0.8 -r 30 -c copy` 只改容器的帧率和包时间戳，仍在真实 Player 中按 1× 播放。ffprobe 确认源为 24/1，试验流为 30/1。FFmpeg 解出的 240 张 RGBA 帧逐帧 MD5 相同。采样结束后临时应用目录被移除。

闲置两档各采样 6.5 秒，走路 0.9 秒，拖拽跟随在 850 ms 稳定期后采样 2.2 秒。记录 `requestVideoFrameCallback` 的 `expectedDisplayTime`、`mediaTime`、`presentedFrames`，按每帧 rAF 最近看到的视频序号统计重复帧。丢帧用三种口径交叉核对：视频质量计数、源时间戳缺口、回调的呈交计数缺口。rAF 中位间隔 16.7 ms。采样起止可能落在刷新边界，视频质量计数与回调数分别保留。

| 场景 | rVFC 回调，前 / 后 | rAF 样本 / 重复，前 → 后 | 质量计数丢帧 / 总数，前 → 后 | 源时间戳缺口 / 呈交缺口，前 → 后 |
| --- | ---: | --- | --- | --- |
| 24 fps idle | 156 / 157 | 389/233 → 391/234 | 0/156 → 0/156 | 0/0 → 0/0 |
| 30 fps idle | 194 / 193 | 388/194 → 385/192 | 0/196 → 3/198 | 0/0 → 0/0 |
| 24 fps 走路 | 21 / 21 | 52/31 → 54/33 | 0/21 → 0/22 | 0/0 → 0/0 |
| 24 fps 等速拖拽 | 53 / 53 | 132/79 → 131/78 | 0/52 → 0/52 | 0/0 → 0/0 |

`frameReportMs` 为 1000 ms。24 fps 在第一次部分采样后每包 24，30 fps 整包范围 29–31，稳定拖拽前后均记录两个 24 帧包，短走路的采样窗口没有完整上报包。产品仍使用 24 fps 素材，表中 30 fps 的质量计数来自临时流。持续回调中两种缺口均为 0。30 fps 又复跑一轮，采得 195 次回调，389 个刷新样本中 194 个重复，质量计数 0/196 丢帧，两种缺口均为 0。同轮走路的质量计数偶发 1/21 丢帧，两种缺口均为 0。

把主进程 16 ms tick 发出 pose 的时间与视频预计呈现时间转成同一时间基准。相位年龄是「呈现时刻减最近一次 pose 发送时刻」。位置保持误差是最近一次发送的位置到相邻两 tick 线性插值位置的距离，用于估计错相上界，不包含 Windows 桌面合成和输入延迟。

走路和稳定拖拽各自的横向逆步为 0。拖拽在两轮均有 129 次呈现采样间的样式变更，说明 60 Hz 可继续接收独立于 24 fps 的变形更新。规律性的错相跳步在这些样本中未复现，保留现行 tick 和帧回调节奏。Windows 真实桌面继续核对观感。

## 复跑

从仓库根安装 Node 24、Python 3、NumPy、Pillow、SciPy、FFmpeg 和 Xorg dummy 驱动。DPI 验证另外需要 `xrandr`、`xwininfo`、`xdotool` 和 CJK 字体。在专用 Xorg 会话中启用 DUMMY 驱动（VideoRam 256000，Depth 24），给 DUMMY0 配置以下模式作为默认模式。窗口定位测量使用没有窗口管理器的会话，避免测试桌面把整个透明窗钳制在可见工作区。

```text
Modeline "1364x1024_60.00" 115.91 1364 1456 1600 1836 1024 1025 1028 1052 -HSync +VSync
```

```sh
export DISPLAY=:91
xrandr --newmode alice-1200x900-60 88.75 1200 1248 1280 1360 900 903 909 926 +hsync -vsync
xrandr --addmode DUMMY1 alice-1200x900-60

cd AliceButler/electron
npm ci
npm run build
node tests/rendering.cjs dpi test-results/rendering --check
node tests/rendering.cjs compositing test-results/rendering
node tests/rendering.cjs timing test-results/rendering
python tests/summarize-rendering.py dpi test-results/rendering
python tests/summarize-rendering.py compositing test-results/rendering
python tests/summarize-rendering.py timing test-results/rendering
npm run precheck
```

DPI 采集会接通和断开 DUMMY1，再改变 DUMMY0 分辨率，结束时恢复单屏基线模式。测旧提交可用 `git archive e04d085 AliceButler/electron` 导出到临时目录，复制这两份测量脚本进导出目录，先构建再去掉 DPI 的 `--check` 采集。使用同一张参考图分析两次色彩。PNG 和逐帧 JSON 存在测试结果目录。 [采集脚本](../AliceButler/electron/tests/rendering.cjs) · [汇总脚本](../AliceButler/electron/tests/summarize-rendering.py)

## 测试记录

- 最小验证覆盖类型构建、12 格 DPI 与 72 个命中点、两种混合模式的截图比较、60 Hz 帧采样和 2 条诊断种子测试。
- 全量通过 38 项 Node 单测、5 项 Python 单测、precheck 的 13 段点播和 8 项接缝、Electron 主集成、4 项交互和 2 项脱敏。播放集成的 122 秒睡眠浸泡复跑检查 8984 帧，空帧、黑帧和页面异常均为 0，最多 2 个视频源。
- 首次浸泡在唤醒后遇到已到期的随机动作抢先呈现。测试改为确认唤醒片段后的首个清醒片段已呈现，并核对主进程已进入 awake。动作调度沿用原实现。
