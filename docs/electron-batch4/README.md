# 第四批性能与可靠性验收

开发线为 `dev/electron-pet`，基线为 `975ecba`。13 个现行 VP9-alpha WebM 的 Git 对象与基线一致。以下运行记录来自云端 Linux/Xvfb 和 Electron 45.3.3。

## 水位与播放连续性

第一批限制了解码槽数，第二批在隐藏或熟睡后释放解码器并修剪缓存。基线缺少按内存采样触发的回收。本批在 `AliceButler/electron/src/main/main.ts` 的 `startTimers`、`memorySample`、`trimPlaybackMemory` 及 renderer 的 `player.ts` 中补齐。默认每 15 秒采样 Electron 进程树（含主、渲染、GPU 等），达到 220 MiB 后用另一解码槽从当前播放位置接续，释放旧槽并通知 Chromium 回收。两次触发至少间隔 60 秒。当前帧画布覆盖纹理修剪窗口。窗口休眠时沿用原有释放路径。

| 云端实验 | 实测 |
|---|---|
| 13 段可见轮播 | 每段显示约 1.7 秒后采样，关闭合成器取帧，13 次私有驻留采样最高 193.31 MiB |
| 触发与回收 | 隔离目录保留默认 220 MiB 水位，将采样周期缩为 3 秒。渲染器分配并写入 112 MiB，在回收通知到达时解除引用。进程树私有驻留 292.87 → 184.11 MiB，下降 108.77 MiB |
| 动作连续性 | 回收跨越 `dangle` 0.7168 → 3.9557 秒，两次读数的动作令牌都是 2 |
| 快速切换且持续取帧 | 156 次切换的录帧进程树私有峰值 604.82 MiB，该场景回收采样 305.66 → 343.30 MiB；连续分配仍可超过水位 |

Linux 统计各 PID 的 Private_Clean 和 Private_Dirty。Windows 读取 Electron 提供的 Private Bytes。触发水位允许瞬时超出；13 段私有内存目标仍为 ≤220 MB。云端数字仅供参考，Windows PC 待艾莉丝部署后复测。

## 双缓冲与逐帧证据

`Player.play` 使用空闲 video 槽启动新片段，收到 requestVideoFrameCallback 后才交接。两路采用互补的不透明度与加法混合，旧槽在淡化结束时释放。快速的新请求优先，过期解码回调不能接管画面。

从 `AliceButler/electron` 运行 `node tests/switch-frames.cjs`（先运行 `npm run build`）。测试遍历全部 13 × 12 个有向切换。耗时从主进程发出动作到主进程收到首帧就绪确认，156 次的中位值 **26.32 ms**、最大值 **64.64 ms**；配置的淡化时长另计 180 ms。

Electron beginFrameSubscription 捕获 1,535 张实际合成器交付的画面，缩为 160 × 90 保留 alpha。空帧判据为 alpha > 100 的像素少于 500；黑帧为不透明近黑像素占画面至少 5%；孤立亮闪或暗闪为整帧亮度总和超出前后两帧范围 25%。三类命中数均为 0。这些结果覆盖本次交付的帧和给定判据。[逐帧数值与动作耗时](switch-frames.csv) · [开头连续 18 帧](switch-sequence.png)

## 每日自检和周报

管家启动后等待初始清理延迟，然后检查本 UTC 日期的结果；重启会复用当天已写结果。管家通过同目录的日期请求触发桌宠顺序解出每段首帧，另查双方 PID、双方心跳与数据卷可用空间。默认候选响应窗口为 240 秒，可用空间下限为 512 MiB。超时、缺文件和死进程均会体现在结果中。运行目录需要配套的 `runner.js`、`daily-check.js`、`watchdog.js` 和 `butler-config.json`。

结果位于 `C:\ProgramData\AliceButler\pet-daily-check.json`，与 `status.json` 同级。实跑时两个 PID 存活，两个心跳分别为 501 ms 和 1,583 ms，13 段均解码成功，剩余 4,820 MiB。异常时托盘头像右下角显示红底白色感叹号，悬停文本显示「每日自检异常」，通过后恢复头像。用失败结果验证标记亮起，再恢复真实通过记录验证清除。[实跑 JSON](pet-daily-check.json)

`pet-stats.json` 保留原有运行快照，并按 UTC 自然日保存最近七天的私有与工作集峰值、每段实际播放启动数、异常退出、自愈及成功聊天往返耗时。相同循环的重复请求、回收时的解码器切换均不增加播放次数。异常退出由上次会话未正常关闭识别，包含强杀或掉电。自愈需有看门狗为刚中断的会话发出的有效重启凭据，且新进程已呈现首帧。聊天样本从投入 inbox 到匹配回复被消费，包含轮询时间。

从仓库根目录导出，参数指向 `pet-stats.json` 所在目录。

```powershell
node AliceButler/pet-weekly.js 'C:\ProgramData\AliceButler' > pet-weekly.txt
```

隔离实跑主动触发 renderer 崩溃，Linux 调度桩记录看门狗实际发出的 `/run /tn AlicePetLaunch`，测试启动第二个真实 Electron 进程并等到首帧。样本覆盖 1 天，记录 1 次异常退出、1 次自愈和 1 条 763 ms 测试聊天回执。Windows 任务计划程序未在云端执行。[真实周报文本](weekly.txt)
