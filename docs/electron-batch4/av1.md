# Electron 45.3.3 的 AV1 透明视频试编评估

当前桌宠应保留 VP9-alpha，编码替换交艾莉丝审计。13 个 AV1 样片都有图像，首帧画布读回的透明像素全部为零。透明桌宠会出现矩形背景。

## 试编与采样

输入为当前 13 个 VP9-alpha WebM。每段 640 × 360、24 fps、10 秒。使用 FFmpeg 的 libvpx-vp9 解出原片颜色和 alpha，split 后将颜色以 yuv420p、libaom-av1 CRF 32 编码，alphaextract 得到的灰度以 libaom-av1 CRF 0 编码。两路均为 cpu-used 8、lag-in-frames 0、GOP 240、b:v 0。保留颜色 WebM 的时间戳、尺寸和轨道信息，设置 AlphaMode=1，并逐帧将灰度 AV1 包封入 Matroska BlockAdditional ID 1。这是用于兼容性验证的实验封装。

ffprobe 检出 3,120 个主图像包，每包都有 Matroska BlockAdditional。逐段解码独立 alpha 码流并与输入的 alphaextract 原始灰度计算 MD5，13 段全部一致。候选体积包括颜色、透明通道和容器。原片已进行过 VP9 压缩，未进行两种编码的等画质率失真评估。

云端 Linux/Xvfb，Electron 45.3.3，每个编码使用独立新配置目录和进程。两组按同一清单顺序，用同一可见 video 播放，每段在首个视频帧回调读回 640 × 360 RGBA；随后用约 1.6 秒的全部 Electron 进程累计 CPU 时间差除以墙钟时间，100% 代表一颗逻辑核心。私有内存为该窗口末各进程 /proc/smaps_rollup Private_Clean + Private_Dirty 之和。CPU 含播放管线和宿主开销。AV1 读数对应画面播放，未获得可用的透明输出。
